# TP2_Exchanges

Адаптеры бирж + общий сборщик стакана.

## Содержимое

- `include/tp2_exchanges/exchange.hpp` — `IExchange`, `OrderSpec`, `OrderBook`.
- `include/tp2_exchanges/orderbook_assembler.hpp` — сборщик стакана (snapshot+delta+seq-guard).
- `bybit_adapter.*`, `binance_adapter.*`, `sim_adapter.*`.

## Bybit (V5) — статус

- REST `/v5/market/orderbook` → `get_orderbook()` возвращает `OrderBook`.
- WS `orderbook.50.<SYMBOL>` → `subscribe_orderbook()` парсит `type: snapshot|delta`, `data: { u, b, a }`, `ts` и применяет через `OrderBookAssembler`.
- Транспорт — пока `Dummy*` (для локальных тестов).

### Тест без сети

```cpp
bybit.subscribe_orderbook("BTCUSDT", 5, [](const TP2::ex::OrderBook& ob){
  std::cout << ob.seq << " " << ob.bids.size() << " " << ob.asks.size() << "\n";
});

ws->send(R"({"type":"snapshot","ts":1730,"data":{"u":1000,"b":[["65000","0.3"]],"a":[["65010","0.4"]]}})");
ws->send(R"({"type":"delta","ts":1731,"data":{"u":1001,"b":[["65000","0.5"]],"a":[["65010","0"]]}})");
```

## Доп материал

✅ 1. Очередь событий (Event Queue)
Что это такое

Вместо того чтобы обрабатывать входящие сообщения приватного WS “в момент прихода”, ты складываешь все события:

обновления ордеров (order)

трейды / исполнения (execution)

обновления позиций (position)

баланс (wallet)

в конкурентно-безопасную очередь (lock-free или std::deque + mutex).

Зачем нужно

✔ не блокирует WebSocket поток
✔ алгоритм обработки (торговая логика) может работать в отдельном треде
✔ позволяет гарантировать “exactly once processing”
✔ можно сделать replay (перепросмотр событий)
✔ минимизирует риск пропуска сообщений под нагрузкой

Плюсы

стабильность под нагрузкой

можно строить асинхронный pipeline (как у Binance Futures API SDK)

супер удобно для логики: цикл while(pop_event(e)) handle(e)

В продакшн-бетах — MUST HAVE.


Автоматическое переподключение приватного WS
Что это такое

Модуль, который автоматом делает reconnect если:

потерялось соединение

Bybit дал ping timeout

твой интернет моргнул

Windows произошёл sleep

Зачем нужно

Приватный поток — это:

stateless

не хранит backlog

если упал — ты пропустил исполнение ордеров!

Пример:
📉 Тебе пришёл fill (order executed) → твой сокет упал → ты его не увидел → стратегия думает что ордер стоит → а он уже исполнился → и выложит второй ордер → и получишь двойную позицию.

Плюсы

живучесть стратегии

не потеряешь ордера

не нужно вручную перезапускать бота

можно поддерживать работу неделями

Обязательная часть для реального бота.

Store актуальные позиции

```cpp
struct Position {
    std::string symbol;
    double size;
    double entry_price;
    double leverage;
    double unrealized_pnl;
}
```

Зачем нужно

Стратегия в любой момент знает:

✔ есть ли открытая позиция
✔ размер позиции
✔ твоя средняя цена входа
✔ нужно ли закрывать/усреднять
✔ нужно ли ставить стоп
✔ какие ордера нужно отменить

Ты не опрашиваешь REST → экономия лимитов → меньше лагов.

Плюсы

стратегия становится “stateful”, но управляемой

можно строить PnL

можно делать управление рисками

быстрые решения локально, без запроса к Bybit

Без этого невозможен нормальный трейдинг.
